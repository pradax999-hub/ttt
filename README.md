# Transfer by Van — перед публикацією

**Актуальное состояние:** можно размещать для тестирования, но готовность к реальным
заказам ещё не подтверждена. В этой среде не запускались браузер, телефон, SMTP и
Stripe. Предыдущие инструкции ниже оставлены как архив, а не подтверждение готовности.

## Точные места и закрытые данные

В последнем обновлении `.env` и `.env.example` не изменялись. Поиск, SMTP и Stripe
используют существующие настройки сервера; новые ключи в код не добавлялись.

Выбранные места сохраняются в `locations`: `pickup`, `destination`, `stopover`.
Каждая точка содержит название, полный адрес и выбранные координаты. Эти же точки
используются в итогах, истории, письме, ваучере, CSV и при повторе маршрута.
Названия не заменяются категорией «вокзал» или «аэропорт». Терминал встречи, если
он применим, показывается отдельно и не подменяет выбранный адрес.

Закрытая страница данных: `/#/wry-ops-8f3c9a71d6e24b50`.
При запуске через `server.js` работает и адрес `/wry-ops-8f3c9a71d6e24b50`.
Ссылки на неё в публичном меню нет. Сложный адрес не является защитой сам по себе.

Для входа используется уже существующий `DRIVER_ADMIN_TOKEN`. Если он не настроен,
страница остаётся закрытой; обхода, пароля по умолчанию или изменения env нет.
После входа доступны поиск по клиенту/адресу/номеру, фильтры дат и статусов,
постраничный список серверных бронирований, детали и CSV текущей страницы.
Из деталей можно перейти к назначению водителя с уже заполненным номером заказа.

API данных защищены `requireOperator` на каждом запросе:

- `POST /api/operator/reservations/search`: фильтры в теле, а не в адресной строке.
- `GET /api/operator/reservations/:orderId`: подробности одной заявки.

Ключ оператора используется только в Authorization, не сохраняется в localStorage,
sessionStorage или URL. Выход, скрытие вкладки и истечение 15 минут очищают данные
экрана и ключ из памяти. Ответы API запрещены к кэшированию. В выдаче нет секретов
окружения, клиентских токенов, хешей доступа или внутренних идентификаторов Stripe.
CSV содержит персональные данные: храните выгруженные файлы только у оператора.

Старые записи показывают только реально сохранённые поля. Если полный адрес ранее
не сохранялся, восстановить его по общему слову «вокзал» достоверно невозможно.
Для проверки выберите два конкретных места, создайте заявку и сравните адреса
в итогах, ваучере и закрытом списке; затем проверьте неверный ключ, выход и обновление.
Браузерный и серверный запуск в этой среде не выполнялся.

## Актуальный запуск

Нужен Node.js 22+. Все новые экраны находятся в `index.html`, API в существующем
`server.js`. Скопируйте `.env.example` в `.env`, заполните собственные значения,
выполните `npm install` и `npm start`. Локально откройте `http://localhost:3000`.
На хостинге задайте точный HTTPS-домен в `CLIENT_URL`. Секреты храните в окружении
сервера, не в HTML, не в Git и не в переписке.

## Поиск отелей

Создайте собственный проект Geoapify (https://myprojects.geoapify.com/) и задайте
`GEOAPIFY_API_KEY`. После перезапуска запрос `hotel` показывает реальные отели рядом
с местом отправления, а название конкретного отеля ищется через Autocomplete.
В строке результата есть название и адрес. Выбор сохраняет конкретные координаты;
первый результат не бронируется автоматически. Данные отличаются от Google Maps.

Публичный Nominatim больше не используется: его политика запрещает автоподсказки.
Без ключа доступны только локальные точки Wayro. Для производственного маршрутизатора
задайте `OSRM_URL`; публичный OSRM по умолчанию подходит только для ознакомления.
Рассчитанное время не учитывает текущие пробки. Котировка действует 15 минут;
backend проверяет её перед оплатой, а не доверяет цене или distanceKm от браузера.

## Настройка GPS

1. Разместите backend и сайт на одном HTTPS-домене.
2. Создайте случайный `DRIVER_ADMIN_TOKEN` длиной не менее 32 символов и задайте его
   на сервере. Например: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.
3. Создайте тестовую бронь, откройте `/#/dispecink` и введите ключ оператора,
   номер заказа, имя, номер автомобиля и телефон водителя.
4. Отправьте полученную ссылку только назначенному водителю. Она действует 12 часов;
   новая ссылка отзывает предыдущую. Главный ключ оператора водителю не передаётся.
5. Водитель открывает ссылку в Safari/Chrome, подтверждает согласие, нажимает
   «Enable GPS» / «Zapnout GPS» и разрешает точную геолокацию телефона.
6. Водитель оставляет страницу открытой и видимой. При уходе со страницы передача
   останавливается. После возврата её нужно включить снова.
7. Клиент видит GPS только у своей брони. При отсутствии сигнала или измерении старше
   60 секунд карта скрывается. Кнопка Stop удаляет опубликованную позицию.

Координаты пассажира не запрашиваются. Симуляция движения выключена. Браузерный GPS
не гарантирует работу при блокировке телефона или в фоне: для этого нужна нативная
водительская программа. Настраивайте телефон на стоянке, не за рулём.

## Письма и оплата

- Для SMTP задайте `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USER`, `EMAIL_PASS` и проверенный
  `EMAIL_FROM`. Копия заявки оператору идёт на настоящий `DISPATCH_EMAIL`.
- SMTP accepted означает приём сообщения сервером, а не попадание во «Входящие».
  Проверьте оба ящика, спам и настройки SPF/DKIM/DMARC.
- `/api/test-email` теперь защищён ключом оператора в Authorization: Bearer.
  Старый открытый test-email.html не обслуживается.
- Без собственного Stripe-ключа онлайн-оплата выключена. Локальная имитация банка
  не используется. Возврат с payment=success не подтверждает списание.
- Вебхук подключается **после размещения**: `/webhook-setup` ведёт на `/#/nastaveni`.
  Добавьте `https://ВАШ-ДОМЕН/api/webhook` в Stripe и затем сохраните
  `STRIPE_WEBHOOK_SECRET` на сервере. События: checkout.session.completed и
  checkout.session.async_payment_succeeded.

## Обязательные проверки

- Тест на двух устройствах: выбор отеля, бронь, письмо оператору, ссылка водителю,
  разрешение GPS, движение, потеря интернета, Stop и истёкшая ссылка.
- Stripe test payment: успех, отказ, отмена, повтор запроса, подтверждение через webhook.
- Постоянный приватный диск `DATA_FILE` и резервные копии. JSON-хранилище рассчитано
  на один процесс; для нескольких экземпляров нужна общая транзакционная БД.
- Не раздавайте корень репозитория статическим сервером. .env, data.json, серверные
  исходники и node_modules должны быть закрыты от HTTP-доступа.
- Подтвердите городские минималки, почасовые тарифы и условия отмены у владельца.
- Изменение/отмена серверного заказа, возвраты, аккаунты и проверка реферальных
  начислений не являются завершённым личным кабинетом: сейчас требуется диспетчер.
- Восстановление заказа из письма на другом устройстве требует клиентской авторизации.
  Статусы рейсов и остальные внешние интеграции также требуют отдельных тестов.

Документация: https://apidocs.geoapify.com/docs/geocoding/address-autocomplete/,
https://apidocs.geoapify.com/docs/places/,
https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/watchPosition.

## 2. Email-підтвердження замовлень
Щоб клієнти отримували листи з підтвердженням:

1. Увімкніть [2FA](https://myaccount.google.com/security)
2. Створіть [App Password](https://myaccount.google.com/apppasswords)
3. В `.env`:
```env

EMAIL_PORT=587
EMAIL_SECURE=false
EMAIL_USER=your-email@gmail.com
EMAIL_PASS=ваш-app-password
EMAIL_FROM="Wayro Transfer <noreply@wayro.cz>"
```

### Перевірка email
```bash
curl -X POST http://localhost:3000/api/test-email \
  -H "Content-Type: application/json" \
  -d '{"to":"test@example.com"}'
```

## 5. Вебхук Stripe — ДОДАЄТЬСЯ ПІСЛЯ ДЕПЛОЮ 🪝

1. Завантажте сайт на домен (HTTPS!)
2. Відкрийте `https://ВАШ-ДОМЕН/webhook-setup` — сторінка з інструкцією і кнопкою перевірки
3. У Stripe Dashboard → Developers → Webhooks → **Add endpoint**:
   - URL: `https://ВАШ-ДОМЕН/api/webhook`
   - Events: `checkout.session.completed`, `checkout.session.async_payment_succeeded`
4. Скопіюйте signing secret → `STRIPE_WEBHOOK_SECRET` у `.env` → перезавантажте сервер

**Важливо:** навіть без вебхука оплата підтверджується — `GET /api/order-status` сам
опитує Stripe API, коли статус `pending`. Вебхук просто робить підтвердження миттєвим.

## 6. API Endpoints
- `POST /api/checkout` – створення замовлення + email клієнту
- `GET /api/order-status?orderId=` – статус оплати (сам перевіряє Stripe)
- `GET /api/driver/:orderId` – позиція водія (live)
- `POST /api/driver/:orderId` – драйвер-додаток шле координати
- `POST /api/sandbox-drive` – емуляція руху водія (тест без додатки)
- `POST /api/test-email` – перевірка email
- `GET /api/flight?fl=LH1400&date=` – статус рейсу в реальному часі
- `GET /api/geocode?q=` – пошук адреси (вокзал, готель, вулиця)
- `POST /api/quote` – реальна відстань по дорогах + ціна
- `GET /api/config` – публічні налаштування (whatsapp, phone)
- `GET /api/webhook/ping` – перевірка, що endpoint живий
- `GET /webhook-setup` – сторінка інструкції з вебхуком
